# NEGATIVE PROMPT — Compose TextField / teclado

Eres un agente que modifica GLMchat (Jetpack Compose). Este archivo es un prompt negativo: describe lo que NO debes hacer. El error que este prompt prohíbe ya ocurrió: la app iba lenta al escribir porque cada tecla recomponía toda la pantalla, re-parseaba Markdown y hacía scroll con el IME.

Si tu cambio viola cualquiera de las reglas de abajo, DESCÁRTALO y hazlo de otra forma.

## NUNCA hagas esto

1. NUNCA pongas el texto de un TextField (composer, búsqueda, edición) dentro de un `ChatUiState` / UiState gordo que la pantalla raíz observa con `collectAsState()`.
2. NUNCA hagas `val state by viewModel.uiState.collectAsState()` en `ChatScreen` (o cualquier pantalla raíz) si ese estado incluye el string del teclado. Un cambio de `input` NO debe invalidar lista, sidebar, top bar, markdown ni partículas.
3. NUNCA actualices el UiState global en `onValueChange` de un TextField. Prohibido: `_uiState.update { it.copy(input = value) }` y cualquier `copy(...)` que toque mensajes, error, flags o listas por cada carácter.
4. NUNCA borres `error`, `info` u otros campos ajenos en cada tecla. `onInputChange` solo puede escribir en el `StateFlow` (o estado local) del texto.
5. NUNCA recolectes el flow del input en el mismo composable que pinta `LazyColumn`, `MessageBubble`, `Markdown` o el drawer.
6. NUNCA crees lambdas nuevas en `items { }` de una lista. Prohibido: `onEdit = { viewModel.editMessage(message.id, it) }`. Usa referencias de método estables (`viewModel::editMessage`) o `remember`.
7. NUNCA uses `padding.calculateBottomPadding()`, `WindowInsets.ime` ni la altura animada del teclado como key de un `LaunchedEffect` que hace `scrollToItem`. Eso dispara scroll en cada frame de la animación IME.
8. NUNCA envuelvas el árbol del chat y el loop de partículas (60/120 fps, O(n²)) en el mismo composable que lee `frameTime` o insets IME. El canvas animado debe ser un hijo aislado; el contenido del chat no puede recomponerse por el teclado ni por cada frame.
9. NUNCA subas a un ViewModel un filtro de búsqueda que solo vive en UI. La búsqueda del sidebar es estado local (`remember { mutableStateOf("") }`), no parte del UiState global.
10. NUNCA asumas que `data class` + `LazyColumn(key)` salvan el rendimiento si pasas lambdas inestables o si el padre recolecta el input. Markdown (`com.mikepenz.markdown`) es caro: no se re-parsea por tecla.

## Cómo SÍ debe estar (contrato actual)

- Texto del composer: `ChatViewModel.input` es un `StateFlow<String>` SEPARADO de `ChatUiState`.
- Solo `IsolatedComposerBar` (hoja) hace `input.collectAsState()`. `ChatScreen` no lee el string del input.
- `onInputChange` asigna `_input.value = value` y nada más.
- Búsqueda del sidebar: estado local en `SidebarContent`.
- `MessageBubble.onEdit` es `(messageId, newContent) -> Unit` pasado como `viewModel::editMessage`.
- Scroll al último mensaje: `LaunchedEffect(messages.size, streamingContent)` SIN padding IME.
- Partículas: `ParticleLayer` aparte de `content()`; pausar el loop si el IME está visible.

## Test mental obligatorio antes de terminar

Ejecuta esto sobre tu diff. Si alguna respuesta es "sí", el cambio está mal:

- ¿Un carácter en el composer emite un `ChatUiState` nuevo?
- ¿`ChatScreen` lee el valor del TextField?
- ¿Algún `MessageBubble` visible se recompone al escribir?
- ¿Markdown se vuelve a ejecutar al escribir?
- ¿Hay una lambda no-`remember` en `LazyColumn.items`?
- ¿Un `LaunchedEffect` depende de insets/padding del teclado?

No entregues código que falle este test.
